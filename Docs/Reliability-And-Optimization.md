# 可靠性与维护说明 · 2026-10-22

## 局内状态

联机开局和重开均由服务端无缝旅行；战斗 GameMode 的初始化显式执行该约定。AGameModeBase 重建 Controller / PlayerState，局内 ASC、GE、武器、商店、选卡及计时器重新建立。本地永久成长子系统不随世界销毁。Pawn 归属修复时钟改为每个 GameMode 一份，世界时间回退也会重新检查。

成长握手按 30 秒期限重试。提交成功冻结本局快照；重复提交拒绝。未提交者超时后退出本局、返回菜单并给出原因，禁止用空快照掩盖失败。

## 奖励和存档

PlayerState 只转交奖励身份，LocalPlayerSubsystem 接管待保存队列。CoreTicker 跨地图重试，一次串行事务合并当前待保存奖励；已提交 RewardId 不重复发放。等待中的奖励不计入已保存余额，升级树显示等待保存状态。暂时写盘失败后切图不再丢弃该队列；磁盘持续不可写且整个程序退出时，内存队列无法保证保留。

当前 Windows 桌面实现：序列化候选、检查业务摘要、写同目录临时文件、关闭并读回逐字节校验；有效旧版本先以相同方式提交到 `_backup.sav`，再用 Windows 同卷替换提交主文件。替换失败时不先删除目标文件。加载时校验摘要，主文件损坏可恢复上一份有效备份；未来版本不会被旧备份偷偷降级。旧的标准 UE v2 存档兼容，首次新提交后获得摘要。摘要用于发现意外损坏，不是防作弊签名。

非 Windows 保存提供者目前只提供备份降级路径，没有宣称平台原子提交保证。存档仍以 `.sav` 形式供 UE 读取；回执不能随意裁剪，否则老 RewardId 会再次发奖。先采样体积与延迟，再决定是否做异步；异步必须串行提交并保留失败回滚。

## 更新与复用开销

HUD 每帧在 Tick 刷新 UMG，DrawHUD 只负责 Canvas，消除同帧的第二次刷新。自动测试仍能通过 Tick 验证无画布 UI。

对象池保留反射数组持有 Actor，用弱引用按精确 Class 建立查找桶。只扫描请求的类，取用仍刷新 Owner、Instigator、位置和朝向；激活/回池仍执行原有碰撞、运动和寿命重置。诊断记录每类命中、未命中和扫描次数。不根据总池一次未命中就自动提高预热量，先看实际武器组合与分类占用。

普通 ActorInfo 诊断使用专用日志的 Verbose，Cue 资产目录限定 `/Game/GameplayCues`；原生 Cue 仍按原注册入口加载。新 Cue 蓝图请放入该目录。

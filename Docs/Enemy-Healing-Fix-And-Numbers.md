# 治疗敌人：DT范围、无治疗量封顶、停滞修复与绿色数字

更新：2026-10-30。本次保留用户已保存的DT数值，不恢复成旧默认值。

以上是当前保存值，不是新硬编码。实际治疗判定和绿色圈统一读取当前行的 `Healing.Radius`。移动中的搜索半径、站位和退避是另一组参数，位于敌人BP的 `EnemySupport → 治疗移动`。

已经删除 `OwnerHealthCapFraction`（按治疗者自身最大生命计算的单跳上限），同时移除恢复比例的隐藏10%钳制。现在每跳恢复量为：

`目标最大生命 × DT恢复比例 × Boss倍率（仅Boss使用）`

最终只限制到目标的缺失生命，不会超过其最大生命。死亡、待死亡结算、归池、满血、自己和其它治疗者仍不会被治疗；目标数量继续按DT配置执行。

## 原地停住的问题与修复

旧逻辑存在两类可复现的“有伤员却不去治疗”：

- 选移动目标时就要求视线无遮挡，墙或场景碰撞挡住后，伤员被直接排除，治疗怪在远处空闲。
- 移动有独立的硬性退避条件。旧默认420cm治疗半径与500cm退避距离会冲突；在这种配置下会放弃靠近玩家的伤员。用户当前1000cm/750cm不等于420cm，不能把旧默认场景直接解释成当前表值。

修复后：

1. 先选有效低血量友军，遮挡不再直接取消移动目标。
2. 治疗判定是否需要视线由新DT字段 **治疗需要无遮挡视线**（`bRequireLineOfSight`）控制，默认关闭，按范围治疗；需要墙体阻断时可以开启。
3. 支援中的紧急退避距离会兼容实际治疗半径：`min(BP退避距离, DT半径 × 0.55)`。空闲仍使用原退避与期望距离；不会把实际治疗半径改成退避距离。
4. 已在有效施法位置时可以停下持续回血。绿色数字用于区分“正在站定治疗”和“没有治疗”。
5. 使用CharacterMovement行走处理坡面、台阶及滑动，而不是手动水平平移；停止时清除残留速度。治疗者每帧提供移动输入，其余怪物的移动方式保留。
6. 缩短近目标的探测步长，避免140cm探测越过目标点，或将可行走地面误当成墙。

开启视线限制后，会尝试寻找友军周围的可见站位并做短程绕障；未增加完整NavMesh迷宫寻路。安全位置被多位玩家或场景包夹时，仍可能需要等待或退避。

## 绿色回血数字

敌人生命实际增加时显示绿色 `+数值`，沿用玩家回血与伤害数字的HUD绘制管线。

- 记录实际增加值，包括最后一跳不足整次回复时的部分治疗。
- 不显示满血的零治疗，不把初始化或对象池恢复血量当成治疗。
- 小于1的恢复保留小数，不强制显示成+1。
- 使用独立的生成周期、序号和累计恢复快照复制；同一帧先回血再受伤，净血量下降时也能显示真实回血。
- 客户端按序消费，避免重复；池周期或过期快照不串到下一只敌人。伤害数字与受击闪白保持各自逻辑。

主要实现：`RogueEnemy.HealingFeedback.cpp`、`RogueEnemyHealingFeedback.h`；绿色样式和文本在 `RogueHUD::AddHealingNumber`。

## 2026-10-30：出生后的怪群跟随

治疗者会先救治搜索范围内的低血量友军；没有伤员时跟随附近普通友军，默认保持300cm后排间距。满血友军仅作为跟随参照，不产生回血和绿色连线；其它治疗者、零血待结算、死亡、归池单位不能作为参照。跟随点靠近玩家时向后调整，玩家进入紧急距离时仍先退避。

`BP_EnemyBase → EnemySupport → 治疗移动 → 治疗者移动设置` 新增“空闲跟随间距”，两种子蓝图继承，也可分别覆盖。原“受伤友军搜索半径”改名为“友军搜索半径”，字段本身不变，保留原配置。默认搜索半径1800cm、间隔0.4秒。确实找不到有效怪群且位置安全时允许待命；进入治疗站位后也允许站定施法。

本轮读取当前DT后确认范围为青叶灵1000cm、祈愿妖精750cm，全部治疗比例、间隔与敌人表保持原值。Development Editor编译及16项定向回归通过，覆盖两种真实BP的地面行走、满血跟随、伤员优先、退避、死亡/池周期切换及真实GAS治疗。未重跑完整长局。

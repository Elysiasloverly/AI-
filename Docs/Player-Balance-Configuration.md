# 玩家数值配置

在内容浏览器打开 `/Game/Data/Player/DA_PlayerBalance`。它是玩家数值的统一入口，共 52 项配置（含 13 种初始武器加成及其上限），现有基础属性和武器加成上限保留原字段和数值，新配置默认沿用原先玩法。

| 分组 | 配置内容 | 默认行为 |
| --- | --- | --- |
| 01 基础属性 | 最大生命/护甲、移动/拾取、恢复/减伤、经验倍率、冲刺、跳跃、第一次升级经验 | 原有 18 项保留 |
| 02 出生状态 | 初始生命比例、初始护甲比例 | 满生命、满护甲 |
| 03 等级与金币 | 升级经验增长倍率、每级固定增长、初始金币 | 倍率 1.3，固定增长 2，金币 0 |
| 04 濒死与复活 | 濒死等待时间、复活生命比例、复活无敌时间 | 等待 10 秒，恢复 50% 最大生命，无敌 1.5 秒 |
| 05 初始武器加成 | 13 种开局属性加成 | 全部为 0 |
| 06 武器加成上限 | 13 种属性加成的可选上限 | 全部为 -1，即不设上限 |

## 如何修改

初始生命和护甲比例以最大值为基准。比如最大生命 200、初始生命比例 0.75，开局拥有 150 生命。生命比例即使设为 0，也会至少保留 1 点生命；最大生命本身为 0 时不会突破该上限。护甲允许从 0 开始。

每次升级后，下一次经验需求按 `四舍五入(本次需求 × 增长倍率 + 固定增长)` 计算，结果至少为 1。第一次需求仍由“基础属性配置 → 升级所需经验”设置。默认从 6 开始，之后依次为 10、15、22。初始等级固定为 1，初始经验固定为 0。初始金币只发放一次，复活和重复接管不会再发。

濒死等待由服务器的截止时刻决定，界面按该截止时刻显示倒计时。调整等待时间不会改变幽灵状态、全队濒死立即结束游戏等规则；倒计时归零后仍等待服务器确认复活。复活生命比例使用复活当时的最大生命，至少恢复 1 点，不改动现有护甲值。无敌时间设为 0 可关闭复活保护。更改配置后重新开始一局进行验证。

初始武器加成是角色带来的额外数值，不是武器最终数值。伤害按绝对数值增加，例如填 `5`，基础伤害 `20` 变为 `25`；攻速加成表示缩短攻击间隔的秒数，部分武器另有换算系数和最短间隔。攻击范围按额外厘米数增加，弹速按额外厘米/秒增加，并按武器系数应用，例如火箭弹速使用 `0.75` 倍、迫击炮使用 `0.5` 倍。这四项都不是百分比。数量与折射使用次数，迫击炮爆炸半径使用额外厘米数。开局加成也受同一资产中的“武器加成上限”限制。例如初始激光数量加成为 1，可让基础数量为 0 的激光在开局解锁；武器是否生成及最终上限仍以武器表为准。

镰刀尺寸加成使用额外比例：`0.2` 表示基础尺寸的 `1.2` 倍，`0.4` 表示 `1.4` 倍。它同时扩大镰刀外观与伤害碰撞范围，不增加环绕距离。对应的“镰刀变大”升级卡每次默认增加 `0.2`，只有实际镰刀数量大于 0 时才加入候选池；最终数量被武器上限限制为 0 时仍不出现。镰刀尺寸加成上限也按额外比例填写，例如 `1` 表示最终最多为基础尺寸的 2 倍，`-1` 表示不限。

## 配置归属

- `DA_PlayerBalance`：玩家属性、开局状态、成长、复活、角色带来的武器加成。
- `DT_WeaponConfig`：每种武器的基础伤害、间隔、数量、弹体等及武器最终上限。
- `DA_UpgradeDefinitions / DT_UpgradeDefinitions`：升级卡内容和每次升级的数值。
- `DA_UpgradeRules`：升级候选和前置条件。
- `BP_RogueCharacter`：外观、材质、模型、输入资源和相机等角色资源配置。

角色上的冲刺等运行数值是 GAS 镜像；不要把它们当作另一份玩家数值来源。`PlayerBalanceAsset` 引用为空时，代码加载上面的默认资产；加载失败才使用结构体默认值。服务器把属性写入 PlayerState 持有的 ASC，再复制给客户端。濒死状态和复活截止时刻一起复制，客户端不自行决定复活。

“恢复默认玩家数值”会重置以上六组全部配置。旧版只重置基础属性，现已补齐武器加成上限和新增各组；点击前请先确认当前自定义数值是否需要保留。

## 旧资产兼容

`BaseStats` 和 `WeaponBonusCaps` 的序列化字段名未变，原有配置不会重置。新增四组在旧资产中缺失时使用上述默认值，保存后正常写入。旧 BP 中的 `ReviveInvulnerableSeconds` 保留为迁移检查字段，实际逻辑以资产中的“复活无敌时间”为准；本项目原 BP 值为 1.5 秒，与新默认一致。

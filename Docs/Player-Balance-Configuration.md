| 04 濒死与复活 | 濒死等待时间、复活生命比例、复活无敌时间 | 等待 10 秒，恢复 50% 最大生命，无敌 1.5 秒 |

## 调试开局武器数量

`DT_WeaponConfig` 的“初始数量”在正常开局会被统一装备规则覆盖：寒弹 1，其余武器 0。为了直接测试任意武器，`DA_PlayerBalance → 调试 → 开局武器` 现在提供 **按武器表初始数量开局（仅编辑器）**，默认关闭。

1. 打开 `/Game/Data/Player/DA_PlayerBalance`，勾选该开关。
2. 打开 `/Game/Data/Weapons/DT_WeaponConfig`，修改需要测试的行的“初始数量”。例如 `Talisman = 3`，开局直接持有 3 张归心符；`Projectile = 0` 可关闭开局寒弹。
3. 保存配置，停止当前游戏并重新运行。PIE 和使用编辑器程序运行的独立游戏均适用；运行中的武器不会随表格编辑即时重建。
4. 测试结束后关闭开关，重新开始一局，恢复正常开局装备。

数量仍受该武器行的 `MaxCount` 限制，负数按 0 处理。本局数量升级通过 GAS 加在基础数量之上；例如开局 3 张灵符，选一次归心符阵后变为 4 张。调试开局不会购买永久树节点，也不会清空或修改存档，专属卡是否入池仍按个人解锁与实际持有条件判断。

开关只用于编辑器，Cook 不携带该字段；打包游戏自动按正常规则开局。联机调试请让各进程使用同一份已保存的资产。更换白天/黑夜地图会重新读开局配置，再叠加继承的 GAS 成长，因此一局测试中应保持该开关和表内基础数量一致。

“恢复默认玩家数值”会同时关闭该开关。它只控制读取初始数量，不改变武器伤害、外观、升级费用或永久节点。

## 如何修改

初始生命和护甲比例以最大值为基准。比如最大生命 200、初始生命比例 0.75，开局拥有 150 生命。生命比例即使设为 0，也会至少保留 1 点生命；最大生命本身为 0 时不会突破该上限。护甲允许从 0 开始。

每次升级后，下一次经验需求按 `四舍五入(本次需求 × 增长倍率 + 固定增长)` 计算，结果至少为 1。第一次需求仍由“基础属性配置 → 升级所需经验”设置：结构体默认从 6 开始，之后依次为 10、15、22；当前 `DA_PlayerBalance` 的首级需求为 8，增长倍率 1.22、固定增长 3，得到 8、13、19、26。初始等级固定为 1，初始经验固定为 0。初始金币只发放一次，复活和重复接管不会再发。

濒死等待由服务器的截止时刻决定，界面按该截止时刻显示倒计时。调整等待时间不会改变幽灵状态、全队濒死立即结束游戏等规则；倒计时归零后仍等待服务器确认复活。复活生命比例使用复活当时的最大生命，至少恢复 1 点，不改动现有护甲值。无敌时间设为 0 可关闭复活保护。更改配置后重新开始一局进行验证。

初始武器加成是角色带来的额外数值，不是武器最终数值。伤害按绝对数值增加，例如填 `5`，基础伤害 `20` 变为 `25`；攻速加成表示缩短攻击间隔的秒数，部分武器另有换算系数和最短间隔。攻击范围按额外厘米数增加，弹速按额外厘米/秒增加，并按武器系数应用，例如八卦炉弹速使用 `0.75` 倍、阴阳玉使用 `0.5` 倍。这四项都不是百分比。数量与折射使用次数，阴阳玉爆炸半径使用额外厘米数。开局加成也受同一资产中的“武器加成上限”限制。当前开局装备规则统一只带一把冰符·寒弹，其它数量/专属初始加成不会绕过永久解锁与本局获取规则；通用伤害、攻速等初始属性仍按配置应用。

银刃尺寸加成使用额外比例：`0.2` 表示基础尺寸的 `1.2` 倍，`0.4` 表示 `1.4` 倍。它同时扩大银刃外观与伤害碰撞范围，不增加环绕距离。对应的“银刃巨化”升级卡每次默认增加 `0.2`，只有实际银刃数量大于 0 时才加入候选池；最终数量被武器上限限制为 0 时仍不出现。银刃尺寸加成上限也按额外比例填写，例如 `1` 表示最终最多为基础尺寸的 2 倍，`-1` 表示不限。

红雾吸血上限使用比例：默认 `-1` 表示不在资产层额外限制，属性层始终钳制在 `100%`；填 `0.5` 表示最多 50%。对应的“红雾吸血”升级卡首次获得为 `20%`，之后每次 `+5%`，同样要求实际银刃数量大于 0，详见 [Scythe-Lifesteal-Upgrade.md](Scythe-Lifesteal-Upgrade.md)。

## 跳跃手感

`DA_PlayerBalance → 基础属性 → 跳跃` 现在有这些字段：

| 字段 | 默认值 | 作用 |
|---|---:|---|
| 跳跃初速度 | 680 | 起跳垂直速度；越高跳得越高 |
| 重力倍率 | 1.8 | 上升/下落的基础重力 |
| 下落重力倍率 | 1.45 | 只在下落阶段额外乘，落地更干脆 |
| 空中控制力 | 0.55 | 空中改变水平方向的能力 |
| 松键跳跃衰减 | 0.45 | 上升中提前松键，垂直速度保留比例（越小人越容易被"按短"） |
| 跳跃输入缓冲(秒) | 0.12 | 落地前按跳，落地瞬间自动起跳 |
| 土狼时间(秒) | 0.10 | 刚走下台阶/斜坡后仍允许起跳一次 |
| 最大跳跃次数 | 1 | 0 表示不能跳 |

默认参数下跳跃上升约 0.39 秒、最高约 1.3 米，下落会明显快于上升。
这些值由 `ARogueCharacter::ApplyBalanceAsset()` 写到 `CharacterMovement`，其中下落重力、输入缓冲和土狼时间由 `UpdateJumpFeel()` 每帧维护；
服务端和客户端执行同一套逻辑，实际手感以本地预测为准。改完资产后重开一局验证。

## 配置归属

- `DA_PlayerBalance`：玩家属性、开局状态、成长、复活、角色带来的武器加成。
- `DT_WeaponConfig`：每种武器的基础伤害、间隔、数量、弹体等及武器最终上限。
- `DA_UpgradeDefinitions / DT_UpgradeDefinitions`：升级卡内容和每次升级的数值。
- `DA_UpgradeRules`：升级候选和前置条件。
- `BP_RogueCharacter`：外观、材质、模型、输入资源和相机等角色资源配置。

角色上的冲刺等运行数值是 GAS 镜像；不要把它们当作另一份玩家数值来源。`PlayerBalanceAsset` 引用为空时，代码加载上面的默认资产；加载失败才使用结构体默认值。服务器把属性写入 PlayerState 持有的 ASC，再复制给客户端。濒死状态和复活截止时刻一起复制，客户端不自行决定复活。

“恢复默认玩家数值”会重置以上六组全部配置。旧版只重置基础属性，现已补齐武器加成上限和新增各组；点击前请先确认当前自定义数值是否需要保留。

## 旧资产兼容

`BaseStats` 和 `WeaponBonusCaps` 的序列化字段名未变，原有配置不会重置。新增四组在旧资产中缺失时使用上述默认值，保存后正常写入。旧 BP 中的 `ReviveInvulnerableSeconds` 保留为迁移检查字段，实际逻辑以资产中的“复活无敌时间”为准；本项目原 BP 值为 1.5 秒，与新默认一致。

## 自动化用例与数值资产

`ARogueCharacter::AddExperience()` 达到阈值会立刻升级并**扣掉阈值**，所以断言"经验加了多少"的用例不能沿用线上资产。

- `Rogue.Gameplay.ExperiencePickup.*` 的夹具自己 new 一份 `URoguePlayerBalanceAsset`，把「升级所需经验」钉成 100 后再 `FinishSpawning`，只验证拾取是否把经验发到角色身上，不验证升级曲线。
- 钉死数值是刻意的：`DA_PlayerBalance` 的首级阈值现在是 2，正好等于用例发放的 2 点经验 —— 走线上资产时 2 点经验会立刻升级并被扣光，断言看到的是 0（曾经的 `MagnetArrivalWithoutOverlap` / `ActivationInsidePlayerAndReuse` 失败就是这个原因，拾取本身没问题）。
- `Rogue.Gameplay.PlayerBalance.*` 同理，用的是会话内构造的配置资产，断言值都来自这份配置。
- 改玩法数值时如果想连带验证曲线，请写在 `PlayerBalance` 套件里，不要在拾取/战斗用例里顺带断言。

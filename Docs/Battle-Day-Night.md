# 战斗地图的白天与夜晚版本

地图统一位于 `/Game/Map/`：

| 地图 | 用途 |
| --- | --- |
| `MainMenu` | 主菜单，保留原有配置 |
| `Battle_Night` | 原 `Minimal_Default` 战斗地图，保留原有夜景 |
| `Battle_Day` | 复制同一战斗地图后调整的白天灯光版 |

两张战斗地图的森林、场景模型和材质、商店、出生点、刷怪范围与不规则轮廓、场景碰撞、环境音、预览相机、关卡脚本与 World Settings 配置保持一致。复制地图时引擎生成的对象/灯光标识不参与场景数值比较。后续对某张地图的摆放修改不会自动同步到另一张。

白天副本将月光改为暖白阳光，调整地图已有的天空光以提亮背光面，关闭夜间点光和聚光灯，调整雾与固定曝光。天空球仅替换独立的白天天空材质实例；森林、地面和角色材质不变，原夜空材质不变。

白天光照可以在大纲的“灯光/白天”下继续调整：

| 对象 | 当前主要设置 |
| --- | --- |
| 白天_阳光 | 强度 3.2，俯角 -55°，偏暖白，光源角度 2° |
| 白天_天空补光 | 指定白天环境 Cubemap，强度 0.85，浅蓝补光 |
| 白天_清透薄雾 | 密度 0.0012，最大不透明度 0.12，起始距离 800 厘米 |
| 白天_曝光与色调 | 手动曝光，补偿 -0.1，中性色调 |
| 天空球 | 使用 `/Game/GameAssets/Environment/Day/MI_DaySky` |

项目采用原有固定曝光和渲染配置，这些强度值针对当前项目调整，不是物理日光照度预设。

默认单人、多人开始游戏和编辑器启动入口进入 `Battle_Day`；应用启动仍显示 `MainMenu`。清完白天第 35 波后，由服务器统一倒计时 30 秒，再以 seamless ServerTravel 带所有玩家进入 `Battle_Night`，从第 36 波继续。

## 昼夜流程与配置

`DA_GameBalance → 08.昼夜阶段 → 昼夜切换` 可设置白天结束波次（35）、切图倒计时（30 秒）、黑夜波次时长（28 秒）、黑夜敌人攻速倍率（2）、两张地图。

白天波次按清场推进：本波普通怪累计名额用完（或可用类型的每波名额全部耗尽），且普通怪与 Boss 全部击败后，才开始下一波，白天不按时间跳波。第 35 波完成生成后先停止所有生成入口，清完场上敌人后才开始 30 秒休整，再进入黑夜第 36 波。清场与休整期间波次停留在 35；世界继续运行，玩家可移动、选卡、购物与复活。清场战斗计入存活时间，休整不计入；若期间团灭，结算接管，不再切图。

倒计时归零后，全员进入黑夜第 36 波。本局击杀数、活动战斗时间及每位玩家各自的等级、经验、金币、GAS 成长、武器数量/专属加成、永久解锁快照、未完成选卡和商店购买计数保留。关店后重新检测新地图商店距离。濒死玩家保留剩余复活时间。新世界正常创建 Pawn、ASC 和武器，不搬运旧世界的对象引用；旧无限升级 GE 的已结算属性作为新 ASC 基值恢复一次，后续升级仍正常叠加。

黑夜普通敌人和 Boss 的近战攻击间隔、远程首发等待与后续攻击间隔均除以 2；移动速度、弹速、伤害不因该倍率改变。对象池每次初始化从原始原型重新计算，不累乘倍率。死亡后重新开始回到白天第 1 波，清空本局成长；本地永久升级存档不受影响。

## 提示 WBP

`/Game/UMG/Menus/InGame/WBP_NightTransition` 继承 `RogueNightTransitionWidgetBase`。默认显示“暮色将至”和“距离黑夜降临：30 秒”。背景、标题、说明、字体、颜色、位置都可在设计器修改。保留名为 `CountdownText` 的 TextBlock，C++ 仅更新它的文字；倒计时文案格式在类默认值的“昼夜提示 → 倒计时格式”修改，保留 `{Seconds}` 占位符。蓝图事件 `OnCountdownUpdated` 可扩展动画。

HUD 自动显示和收起此 WBP。GameState 复制阶段与服务器截止时刻，各客户端按同步后的服务器时间计算剩余秒数，不各自启动 30 秒计时器。提示不捕获鼠标或键盘；团灭立即收起，切图销毁时移除。显示到 0 后等待服务器完成切图。

UI 类引用位于 `DefaultGame.ini → RogueHUD.NightTransitionWidgetClassPath`；单人入口由 `SinglePlayerMapPath`、多人由 `RogueRoomSubsystem.BattleMap`、编辑器由 `DefaultEngine.ini.EditorStartupMap` 决定。

打包 `MapsToCook` 已包含主菜单及两张战斗地图。旧地图名 `Minimal_Default` 已移除，旧路径由 PackageRedirect 兼容；代码默认路径和当前教程已更新。`Tools/probe_maps.py` 是只读检查工具，验证三张地图及入口、GameMode。

## 每波普通怪名额

在 `DA_GameBalance → 刷怪数量与速度` 配置“第1波普通怪总数”“每波增加的普通怪总数”“每波普通怪总数封顶（0=不限）”。当前为 24、2、0，即第 N 波累计名额为 `24 + 2 × (N−1)`，Boss 另计；这组生成名额在白天与黑夜均生效。原有“基础场上上限”等字段仍限制同时存活数，不等同于本波累计名额。

怪物按原有间隔分批生成，成功生成才消耗名额；失败重试不扣名额。击杀会释放存活位置，但不会退还本波累计名额。若全体可用类型的 `MaxSpawnPerWave` 已用完，则本波停止生成，不会为了凑满总量绕过类型限制。白天须完成生成并击败全部敌人（包括 Boss）才下一波，生成间隙短暂空场不会提前切波；黑夜则到时切波，不等清场。

服务端 GameMode 统一推进波次，客户端继续读取 GameState。日夜切图保留真实存活时间与玩家成长，直接打开黑夜地图从白天结束波次的下一波开始。旧 `WaveDuration` 字段只为旧包保留，不再展示或参与运行。

## 黑夜按时间切波

进入黑夜时，从第 `DayWaveCount + 1` 波开始，单独将黑夜波次时钟归零。`DA_GameBalance → 08.昼夜阶段 → 昼夜切换 → 黑夜波次时长（秒）` 默认28秒，可调整，最低1秒。白天实际打了多久、休整倒计时多久，都不会让黑夜刚开始就跳过多波；本局存活时间继续保留。

每满一个周期进入下一波，不等待普通怪、Boss或本波生成名额用完；提前清场也不会提前进入下一波。旧敌人继续留场占用存活名额，每类每波计数和普通怪累计名额在新波重置，未生成的名额不结转。场上数量已满时波数仍推进，但暂不生成新的普通怪；Boss单独生成，已有Boss存活时不叠加新Boss。

卡帧跨过多个完整周期时按经过周期推进波数，并保留本周期余量，不集中补刷已跳过波次的敌人。切波由服务器GameMode统一处理，客户端仍只读取GameState，没有各自独立切波计时器。原有35波清场、30秒休整、黑夜攻速翻倍保持。

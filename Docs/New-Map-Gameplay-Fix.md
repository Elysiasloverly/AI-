# 新地图玩法与碰撞修复

2026-11-02。适用于五主题十张战斗地图。

## 为什么看不到怪物，随后不能控制

此前的地图生成脚本错误地把 DefaultGameMode 设为原生 RogueGameMode，覆盖了原地图的 BP_RogueGameMode。敌人类型到蓝图的映射存在蓝图默认值里，原生类没有这些映射，因此会退回没有模型的原生敌人，保留碰撞和伤害。独立诊断中也观察到玩家进入终态后无法继续控制的情况。

十张地图现在统一使用 `/Game/BP/Framework/BP_RogueGameMode`，恢复 18 种敌人蓝图映射。关卡的世界设置覆盖优先于项目的全局默认 GameMode；只看 C++ 基类或项目默认配置不能证明运行时已经配置好外观。

新增回归检查 BattleMapsUseEnemyBlueprintsAndGameplayCollision，会读取地图池中的每张地图，检查其实际 GameMode 是否有敌人蓝图映射；同时检查四个场景模型是否配置独立碰撞。

## 为什么地面会挡路

四份合并模型原本把建筑、铺砖、草、枝叶、花瓣等全部用于复杂碰撞。铺砖高度和接缝经过世界缩放后形成小台阶，装饰也可能阻挡玩家、敌人或出生胶囊。单纯检查向下射线命中，不足以证明可以站立和行走。

四个模型现在分别绑定独立的 GameplayCollision 静态网格，位于 `/Game/FourMaps/Map01–04/Collision`。原视觉模型保留，不把简化碰撞网格额外摆进地图。

碰撞生成方式：从原 Blender 场景提取可走表面，重采样并平滑铺砖接缝；保留桥面的大致坡度，移除草、花瓣和细小装饰的阻挡，保留建筑、大岩石和主要树干。实际角色的移动规则、护盾和武器数值没有为了过图而放宽。

冰湖商店桥的初版轮廓还有一段误框到水面。现在刷怪轮廓、内孔与空气墙按连续的实际碰撞面裁剪，商店与主岛保持连通。新地图的四个出生点移到主战斗空地，避免出生在狭窄的装饰入口。旧森林商店摆放保持原样。

## 以后改地图

复制战斗地图后，先检查世界设置中的 GameMode 为 BP_RogueGameMode，再检查刷怪区域、出生点和商店。重新导入四个视觉模型后，还应检查静态网格的 Complex Collision Mesh 仍指向对应 GameplayCollision。改动地形结构时，碰撞网格、刷怪轮廓与空气墙需要同步更新。

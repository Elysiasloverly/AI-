# Boss 技能插槽

当前实现采用“怪物原有攻击 + Boss 追加技能”。普通攻击保持现有配置与执行通路。九种正式符卡、抽取规则、图标和配置入口见 [Boss 符卡](Boss-Spellcards.md)，本页保留可复用的插槽框架说明。

## 编辑入口

打开 `/Game/BP/Enemy/Common/BP_EnemyBase`，选择继承的 **BossSkills / Boss技能插槽** 组件。在“技能插槽”数组里添加数据表行引用。基类配置会被子蓝图继承，子蓝图可覆盖自己的列表。

配置表为 `/Game/Data/Enemies/DT_BossSkills`，行结构 `FRogueBossSkillRow`。表内包含九条正式技能。三条默认禁用的时间线模板保存在 `/Game/Data/Enemies/Templates/DT_BossSkillTemplates`。基类的显式插槽留空，因此从配置好的目录随机抽取；最终波使用完整目录。

制作具体技能时，先创建继承 `RogueBossSkillAbility` 的 Gameplay Ability 蓝图，将其指定到表行“技能能力类”，实现 `OnSkillPulse`，再开启表行并添加到敌人的技能列表。原生能力类本身只执行时间线，不产生弹体或伤害。

时间线由原生父类启动，技能蓝图使用下述回调扩展内容，保留父类 ActivateAbility / EndAbility；不要另写一套 Event ActivateAbility 和循环计时来重复调度。

普通个体不会获得 Boss 能力，不运行该组件 Tick，也不复制技能状态。是否成为 Boss 由本次 `InitializeEnemy` 的运行时 Profile 决定；治疗型 Boss 也可以独立获得技能。

## 节奏与调度

```text
满足初始延迟 / 血量条件 / 本技能冷却
  → 按权重选择一个技能
  → 蓄力预警
  → 开始持续施法，按施法间隔重复攻击
  → 到达持续时间的截止点，停止本次施法
  → 清除登记的持续区域
  → 收招恢复
  → 技能结束，开始该插槽的冷却
```

每只 Boss 同时运行一个插槽。技能结束后，各插槽分别计算冷却；权重 0 不参与释放。最低/最高生命比例限制该技能可开始释放的阶段，不会在中途跨过阈值时强行取消。

| 参数 | 含义 |
|---|---|
| 出场后首次延迟 | 本次成为 Boss 后，第一次允许使用该技能的时间 |
| 结束后冷却 | 正常结束或中止后开始计时；最短运行间隔为 0.1 秒 |
| 蓄力预警时间 | 发射前等待时间，0 表示直接释放 |
| 持续时间 | 所有 Boss 技能默认 10 秒，三轮烈日也会在持续期间反复发出三颗一组的火球 |
| 施法间隔 | 默认 0.5 秒，至少 0.02 秒。持续期内按间隔攻击或治疗，天裁按此间隔结算伤害 |
| 每场限次 | 回生为 1，金刚为 3，其他为 0，表示不限整场使用次数 |
| 收招恢复时间 | 攻击结束后保留的恢复窗口 |
| 暂停普通攻击 | 覆盖蓄力、释放和恢复；已发出的普通子弹继续原有生命周期 |
| 暂停移动 | 阻止现有原生及通用蓝图移动入口，不修改角色移动属性 |
| 需要存活玩家目标 | 开始时选取存活目标；目标失效则中止。自身环形招式可关闭 |

默认从蓄力开始固定目标位置，不在预警结束瞬间偷换落点。每次发射前会检查 Boss 状态、出生代次和目标。时间线独立于普通攻击计时器，不自动套用普通攻击的攻速缩放。

## 蓄力、连发与持续效果的实现接口

能力蓝图中的以下回调仅在服务器执行：

- `OnChargeStarted(Context)`：设置本招式的权威准备逻辑。
- `OnSkillPulse(Context)`：执行一次实际攻击，`PulseIndex` 从 1 开始。伤害、弹体与命中逻辑放在此处或其调用的原生实现。
- `OnRecoveryStarted(Context)`：进入恢复窗口，停止需要显式停用的攻击资源。
- `OnSkillStopped(bCancelled)`：完成与中止都会调用，用于额外清理。

技能自己创建的预警 Actor、持续伤害区或光束，可通过 `TrackActorUntilSkillEnds` 登记。登记对象会在进入恢复、取消或结束时销毁；不要登记敌人、玩家或需要独立飞行的普通弹体，也不要将应归还对象池的对象登记为待销毁对象。池化对象应在 `OnRecoveryStarted` / `OnSkillStopped` 中调用自己的归还接口。

持续施法使用固定截止时间和一次性计时器逐次安排。卡顿后跳过已经错过的攻击，超过截止时间直接收招，持续时间不会被延长。光束和金刚只创建一次持续实体，回生按时间进度恢复，并在正常收招时补齐到满血。GAS EndAbility 负责结束能力任务和潜在动作，原生类另外清理自己的序列计时器。自定义异步逻辑优先使用 AbilityTask，并保留父类生命周期。

伤害、范围和具体招式参数继续使用 DT；材质、模型、预警样式等保留在表现 BP。新增的原生公共类不依赖具体怪物枚举。

## 联机表现

组件的 `OnPresentationChanged(Context)` 用于本地创建、更新和移除持续预警。通过服务器时间和 `PhaseEndServerTime` 计算剩余时间；晚收到状态时恢复当前阶段，不重新播放完整蓄力。

`OnPulseCosmetic(Context)` 用于每次发射的短暂音效或动作。它是不可靠多播，可能丢失；具体攻击仍须使用其自己的权威弹体及客户端表现同步通路。禁止在这些表现回调里再次结算伤害，也不要根据复制的 PulseIndex 追补历史弹体。

状态包括技能行、CastId、出生代次、阶段截止时间和锁定位置。旧出生代次的表现消息会被忽略；回池、复制状态到达顺序变化和退出关卡都会触发表现清理。`GetSkillCooldownRemaining` 目前供服务器调度/调试查询，客户端没有完整的所有插槽冷却列表。

## 取消与兼容

死亡或零生命、回池、销毁、切图、整局结束、必需目标失效都会中止技能。死亡/回池的强制中止不受普通“不可打断”设置影响。授予与清除只管理 Boss 自己的能力句柄，不清空普通攻击能力。

Boss 大招互斥会覆盖普通接触攻击、远程攻击、飞行连发和固定法阵的伤害入口。已发出的普通弹体不被清除。自行在蓝图里实现完全独立的移动/伤害逻辑时，也应检查基类提供的 `AreNormalAttacksSuppressed` 和 `IsBossSkillBlockingMovement`。

自定义技能可从模板表复制行，并配置持续时间、施法间隔和恢复窗口。`OnSkillPulse` 仍表示一次实际释放，`PulseIndex` 供表现和招式内部排序使用。旧表的释放轮数和释放后维持字段只供兼容换算，正式表和模板已重存为持续时间配置。

## 代码入口

- `Enemies/Data/RogueBossSkillTypes.h`：表行与复制状态。
- `Enemies/Components/RogueBossSkillComponent.*`：插槽授予、选择、冷却、互斥和表现同步。
- `AbilitySystem/Abilities/RogueBossSkillAbility.*`：蓄力、逐次释放、维持、恢复和中止。
- `Enemies/RogueEnemy.LifeCycle.cpp`：初始化、死亡及回池接入。
- `Debug/Tests/RogueBossSkillTests.cpp`：真实 GAS 能力时序和生命周期定向验证。

## 本轮验证

Development Editor 编译通过。14 项定向检查全部通过：5 项 Boss 插槽验证、3 项普通攻击原型回归、6 项飞行敌人回归。9 项含测试临时世界缺少刷怪区域的预期警告。

Boss 检查覆盖仅 Boss 授予、治疗型 Boss 独立授予、普通攻击互斥、蓄力不提前释放、逐次连发、独立冷却、维持阶段、恢复前销毁持续区域、强制中止、对象池复用、目标失效和长帧不整轮补发。

另在同一编辑器的房主/客户端两个 PIE 世界中，使用没有攻击内容的临时测试技能，验证了蓄力截止时间与锁定位置复制、第二次释放进度同步、中止同步和回池后的待机状态。测试行及敌人 CDO 调整只存在于验证进程内存，没有保存。

首轮插槽验证覆盖了模板与继承关系。正式符卡的定向验证另外覆盖白天／黑夜／终局选取数量、血条快照、回血和伤害转化次数，以及第 100 波清场结算。

# 敌人配饰碰撞与斜面回落

敌人继承 `ARogueEnemy`，模型和配饰（StaticMesh、SkeletalMesh 等 MeshComponent）负责显示，根胶囊负责与地面、场景、弹体的碰撞查询。接触伤害仍按距离结算。

## 本次原因

实际蓝图中的人物模型及新增扫帚配饰使用了 `BlockAllDynamic` 等阻挡设置。原有胶囊忽略 Pawn 的配置无法替它们取消碰撞，因此会互相顶挤。敌人 CharacterMovement 还保留了零重力，离开斜面或被碰撞挤高后不能正常下落。

敌人的移动逻辑通过扫掠位移更新胶囊位置。它绕过了 CharacterMovement 自己的水平位移，因此移动后还必须重新检查地面，避免继续使用上一个位置的地面缓存。

## 当前行为

- 蓝图组件构造完成、BeginPlay、服务端出池及客户端活动状态更新后，所有敌人自身的 MeshComponent 统一关闭碰撞、重叠、物理模拟、可踩踏和导航影响。
- 初始化与激活蓝图回调结束后再次应用，覆盖这些回调创建或重新启用的模型碰撞。
- 不改模型、材质、相对变换或缩放；独立的攻击触发 ShapeComponent 不在处理范围内。
- 敌人为地面角色，原生默认重力为 1；旧蓝图的零、负数或无效重力会补正为 1，已有有效正重力保留。关闭 CharacterMovement 对物理物体施力。
- 每次原生或蓝图移动接口完成扫掠位移后，强制下一次 CharacterMovement 更新重新检查地面。走出坡面、台阶后自然下落，不强行锁死世界 Z。

在敌人蓝图里新增普通静态网格体配饰即可，游戏中会自动按外观组件处理。需要真正的攻击区域时，使用独立的碰撞形状组件和明确的碰撞通道，避免用外观网格代替攻击判定。

## 回归入口

`Rogue.Gameplay.EnemyCollision` 覆盖实际 14 个敌人蓝图（Base + 13）、配饰与胶囊碰撞、对象池复用、新增配饰外观保留、有效重力覆盖，以及斜面落地、离开坡面与受向上位移后的回落。

验证结果：Development Editor 和 DebugGame Editor 均编译成功，两种配置各 63 项回归测试全部通过。当前地图单机验证 16 只敌人，联机房主验证 16 只、加入者验证 23 只，未发现配饰碰撞或异常升空。

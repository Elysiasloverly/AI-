# 升级树使用与配置

升级树入口位于 `WBP_MainMenu` 的“升级树”按钮。页面分为“武器与专属卡”和“基础属性”，花费冰砖后立即保存到本机；返回按钮或 Esc 可以回到主菜单。

## 当前规则

- 每击败一个 Boss，本局每位参与玩家各获得 **1 个冰砖**，包括正在濒死等待复活的玩家；旁观者不领取。同一只 Boss 的同次生成不会重复发奖，对象池再次生成的 Boss 可以正常发奖。
- 每局开始仅装备 **1 张御札**。御札及其数量升级卡默认开放，一般属性卡默认可以进入卡池；护甲相关卡需要先解锁护甲。
- 其他武器每把花 **5 个冰砖**永久解锁。解锁后，该武器的首次获取卡才能出现在本局升级和商店卡池，仍需在战斗中抽取获得，开局不会直接装备。
- 每张武器专属卡单独花 **5 个冰砖**，需要满足配置中的全部前置节点。例如“银刃巨化”和“红雾吸血”分别购买；同一分支必须沿前置从上向下逐个购买：银刃 → 银刃数量卡 → 银刃巨化 → 红雾吸血；极限火花 → 数量卡 → 星尘折射；阴阳玉 → 数量卡 → 爆炸范围。不能跳过中间节点。
- 武器的“首次获取”和“继续增加数量”共用同一种数量卡：解锁武器允许第一次抽到它；已经持有后，继续抽数量卡还需要解锁对应的数量升级节点。银刃巨化、星尘折射等专属效果还要求本局已经持有对应武器。
- 新玩家的护甲上限和当前护甲均为 **0**。先花 **3 个冰砖**购买“解锁护甲”，启用 `DA_PlayerBalance` 中的基础护甲；之后才能购买基础护甲等级和刷新护甲相关卡。护甲的永久属性最多再升 5 次，每次 3 个冰砖。
- 基础属性每项最多 **5 级**，每级 **3 个冰砖**。永久属性在下一局开局写入一次；复活、重复接管角色不会再次叠加。

| 基础属性 | 默认每级增加 | 5 级合计 |
| --- | --- | --- |
| 攻击力 | 3 点 | 15 点 |
| 最大生命 | 20 点 | 100 点 |
| 基础护甲 | 10 点，须先解锁护甲 | 50 点 |
| 移动速度 | 30 厘米/秒 | 150 厘米/秒 |
| 经验吸取半径 | 40 厘米 | 200 厘米 |
| 生命恢复 | 每秒 0.2 点 | 每秒 1 点 |
| 攻击间隔缩短 | 0.03 秒 | 0.15 秒，仍受各武器最短间隔限制 |
| 经验获取倍率 | 0.05，即 5 个百分点 | 0.25，即 25 个百分点 |

## 改数值与节点关系

唯一的升级树配置资产：`/Game/Data/Progression/DA_UpgradeTree`。

打开“全部升级节点”后，可以修改名称、说明、每级冰砖花费、每级属性增加值及前置节点。基础属性最大等级最多为 5；武器、专属卡和护甲解锁节点只购买一次。前置数组中的节点全部解锁后，当前节点才可以购买。

`NodeId` 是存档使用的永久标识，已有玩家存档后应保持不变；修改显示名称不会影响存档。不要把新付费节点勾选为“初始免费解锁”，也不要把同一个 `NodeId` 用于多个节点。创建新卡牌类型时，还需要补充局内卡牌效果和卡池规则，单独增加树节点不会生成新的武器逻辑。

布局自动读取 `DA_UpgradeTree` 的前置节点数组：无前置的节点按资产数组顺序横向排列在第一阶；有前置的节点生成在父节点下方，后续依赖继续向下形成分支。一个节点有多个前置时，必须全部满足，并排在最深前置的下一层。同一前置派生多个节点时，会自动分列留出空间。旧 `TreePosition` 不再决定位置；只需修改前置关系，无需手填坐标。

`DA_PlayerBalance` 继续提供玩家原始基础属性，升级树仅叠加永久增量。基础护甲只有在 `Armor.Unlock` 已购买时才启用，避免两处重复填写一份起始护甲。

## 修改 WBP 样式

- 整页：`/Game/UMG/Menus/Progression/WBP_UpgradeTree`，父类 `RogueUpgradeTreeWidgetBase`。
- 单张节点：`/Game/UMG/Menus/Progression/WBP_UpgradeTreeNode`，父类 `RogueUpgradeTreeNodeWidgetBase`。
- 入口：`/Game/UMG/Menus/MainMenu/WBP_MainMenu` 的 `SkillTreeButton`。

字体、背景、卡片、按钮和动画都可以在 WBP 的设计器中修改。整页“类默认值”中的 `NodeWidgetClass` 指定节点 WBP；卡片占位会自动读取节点 WBP 设计器的自定义尺寸或根 SizeBox 的期望尺寸；修改设计器自定义尺寸后编译并保存 WBP，尺寸会同时保留到打包版本。特殊自绘卡片可在节点 WBP 的“节点尺寸覆盖（零为自动）”中明确指定大小。页面的 `NodeSize` 仅作为无法测量时的备用尺寸；`NodeSpacing` 控制最小行列间距，`CanvasPadding` 控制内容留白。节点变大时分支和层间距自动扩开，连线跟随节点真实边缘，名称、字体、背景等样式保持在 WBP 中编辑。

保留整页控件的名称与类型：`TreeCanvas`（CanvasPanel）、`TreeScrollBox`（ScrollBox）、`TreeContentSize`（SizeBox）、`WeaponsTabButton`、`AttributesTabButton`、`CloseButton`（Button）、`IceBricksText`、`StatusText`、`SectionText`（TextBlock）。其中画布和节点类是生成树内容所必需的；按钮及文字名称用于自动绑定功能。

节点内自动绑定的控件为 `StateBorder`（Border）、`PurchaseButton`（Button），以及 `TitleText`、`DescriptionText`、`CostText`、`RankText`、`StateText`、`PrerequisiteText`、`PurchaseLabel`（TextBlock）。可以移动、重新排版或添加装饰；删除或改名后，相应的自动更新和点击绑定会失效。

节点事件 `OnViewDataChanged` 提供名称、说明、费用、等级及状态。需要自己控制状态外观时，勾选 `bBlueprintHandlesStateStyle`，在这个事件中制作配色或动画；文字和购买按钮的可用性仍会自动更新。整页还提供 `OnTreeRefreshed` 与 `OnPurchaseResult`，便于添加余额动画、购买音效或提示。

如果自行制作入口或界面，可以调用 `RogueProgressionSubsystem.GetForPlayer`，传入当前 WBP 的 Owning Player；通过 `GetIceBricks`、`GetSnapshot`、`GetDefinition` 读取数据，通过 `TryPurchaseNode(NodeId, OutFailure)` 购买，并绑定 `OnProgressionChanged` 刷新界面。不要在蓝图中自己先扣冰砖再设置等级。

主菜单打开页面仍通过 HUD 的 `OpenUpgradeTree`，关闭通过 `CloseUpgradeTree`；这两条路径同时处理主菜单显示与焦点。界面类路径位于 `DefaultGame.ini` 的 `UpgradeTreeWidgetClassPath`。

`Tools/create_upgrade_tree.py` 用于创建缺失的资产，重复运行会保留已有升级树布局。带 `RogueRebuildUpgradeTreeWidgets` 参数会重建这两张升级树 WBP 的默认布局，修改样式后不要随意使用该参数。

## 存档与联机

默认本地玩家 0 的槽名是 `Baka_UpgradeTree_Player0`。编辑器运行时的文件位于 `F:\AI_WorkSpeace\baka\Saved\SaveGames\Baka_UpgradeTree_Player0.sav`；打包后的目录以运行环境的 `Saved/SaveGames` 为准。分屏玩家使用各自的 Player 索引，远端玩家使用自己电脑上的存档。更换电脑不会自动同步进度。

加入战斗时，各玩家仅上传节点等级快照；服务器校验已知节点、等级上限和前置关系后，为该玩家冻结本局快照。服务器按每位玩家自己的快照生成升级及商店卡池，其他玩家和房主的解锁不会替代你的进度。本局获得的冰砖由各自客户端保存；中途修改永久进度不会重写本局已经初始化的属性。

这是以本地存档为基础的合作联机方案：服务器检查快照结构和节点规则，但本地存档不是防修改凭证。购买及奖励先在副本中计算，写盘成功才提交；失败会保留原余额和等级。无法读取或版本过新的存档会原样保留，并显示存档不可写提示，不会自动覆盖成新档。

旧版存档已经付费购买上层卡时，会在读取时补齐这次新增的中间前置，保留原余额、已购卡片和 Boss 奖励记录。新存档按顺序逐项付费。基础属性仍按 1→2→3→4→5 逐级提升。

## 编辑器调试冰砖

在 `DA_UpgradeTree` 的“调试 / 冰砖”分类中，点击“读取当前冰砖”，填写“目标冰砖数量”，再点击“应用冰砖数量”。这是一次设置余额的操作，之后购买会正常扣除，不会在下次开局恢复成目标数量。

未运行游戏时修改本地存档；运行 PIE 时修改选定窗口、本地玩家的实时余额，并立即保存和刷新升级树。默认选本地玩家 0、PIE 窗口 0；多窗口联机时可展开高级选项指定窗口编号。独立进程客户端需要在自己的进程中应用。已有解锁与 Boss 奖励记录会保留，不可读或较新版本的存档不会被覆盖。

这些调试字段只存在于编辑器数据中，正式打包不携带，应用操作也不会在正式运行时生效。

## 恢复配置与重置进度

这两个操作在 `DA_UpgradeTree` 中分开提供：

- **恢复默认节点配置（不重置存档）**：替换资产内的节点名称、说明、费用、免费标记和前置关系；会覆盖自定义节点配置，但不影响本地已经购买的等级。
- **重置本地解锁进度（保留冰砖）**：在“调试 / 进度”中点击，清除所选本地玩家已购买的武器、专属卡、护甲解锁和全部基础属性等级，立即保存。保留当前冰砖，不退还已花费的冰砖，也保留 Boss 奖励记录防止重复领取。默认配置下仅御札及御札数量卡保持开放；若修改过“初始免费解锁”，则以当前配置为准。节点配置与 WBP 样式不受影响。

重置沿用“调试 / 冰砖”中的本地玩家索引和 PIE 窗口编号；运行 PIE 时升级树页面立即刷新，停止 PIE 时直接修改对应本地存档。永久属性及联机卡池使用本局开局快照，需要重新开始一局才会采用重置结果。若希望冰砖也归零，再将目标冰砖设置为 0 并点击“应用冰砖数量”。操作结果显示在冰砖调试分类中的“操作结果”。
